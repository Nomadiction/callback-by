# Эвристики поиска и заполнения формы

Документ описывает логику `src/form_finder.py` и `src/form_filler.py`. Все списки ключевых слов вынесены в `data/keywords.json` — менять их можно без правок кода.

## Этапы

### 1. Поиск телефонного input на текущей странице

Селекторы (составляются из `phone_field_hints` + базовый `input[type="tel"]`):

```css
input[type="tel"]
input[name*="phone" i], input[id*="phone" i], input[placeholder*="phone" i]
input[name*="tel" i], …
input[name*="телефон" i], input[placeholder*="телефон" i]
input[name*="номер" i], input[placeholder*="+375"]
…
```

Модификатор `i` — case-insensitive. Берём первый **видимый** (`is_visible()`) кандидат среди первых 10.

### 2. Если шаг 1 пуст — кликаем триггер модалки

Перебираем тексты из `form_triggers`:

```
перезвонить, перезвоните мне, обратный звонок, заказать звонок,
заказать обратный звонок, callback, call back, request a call,
пазваніць, адваротны званок
```

Для каждого ищем `button:has-text(...)`, `a:has-text(...)`, `[class*="callback" i]:has-text(...)`. Кликаем первый видимый, ждём появления `tel`-input до 5 сек, повторяем шаг 1.

### 3. Контейнер и submit

От найденного input идём вверх по DOM:

1. Сначала — ближайший `<form>` (`xpath=ancestor::form[1]`).
2. Если формы нет (модалка без `<form>`-обёртки) — берём ближайший `div`/`section`, содержащий кнопку или `input[type=submit]`.

Submit ищется внутри контейнера в порядке:

1. `button[type="submit"]` / `input[type="submit"]` (видимый).
2. По текстам из `submit_button_hints`: «отправить», «заказать», «перезвоните», «отправь», «submit», «send», «ок», «позвонить».

### 4. Поле сообщения (опционально)

Селекторы из `message_field_hints`: `textarea`, `input[name*="message" i]`, `textarea[name*="комментарий" i]` и т.п. Берётся первый видимый внутри контейнера. Если нет — заполнение пропускается, флаг `message_sent=False`.

### 5. Заполнение телефона

Перебираем 5 вариантов из `phone.variants(...)`:

```
+375XXXXXXXXX
+375 29 123-45-67
+375 (29) 123-45-67
80 29 123 45 67
291234567
```

После каждой попытки читаем `input_value()` и считаем цифры. Если ≥ 9 — считаем удачным (input-маска приняла). Иначе — следующая вариация.

Это работает с типичными масками вроде `+375 (__) ___-__-__`, которые отбрасывают «лишние» символы.

### 6. Submit и детекция успеха

Кликаем submit с таймаутом 4 сек. Затем ждём `networkidle` (4 сек) и читаем `body.inner_text()`. Ищем подстроки из `success_indicators` (case-insensitive):

```
спасибо, ваша заявка, заявка принята, заявка отправлена,
мы свяжемся, мы перезвоним, перезвоним вам, успешно, thank you
```

- Найдено → `Status.SUCCESS`.
- Не найдено, но клик прошёл → `Status.SUBMITTED` (форма отправлена, но подтверждение не распознано — могло быть, могло не быть).
- Клик упал → `Status.FAILED` с текстом ошибки.

## Известные сценарии, где эвристика не сработает

| Сценарий | Симптом | Workaround |
|---|---|---|
| Виджет JivoSite в iframe | Форма не находится | Добавить обход `page.frames` |
| reCAPTCHA / hCaptcha | `SUBMITTED`, но реально не ушло | Капчу не обходим, считается false-positive |
| Cloudflare challenge | `UNREACHABLE` или таймаут | Не обходим |
| Многошаговая модалка (выбор темы → форма) | `NO_FORM` | Расширить `form_triggers` или добавить второй уровень кликов |
| Input с кастомным React-стейтом, игнорирующим `type()` | Цифры < 9, все варианты падают | Добавить вариант через `evaluate()` с диспатчем `input` event |

## Как настроить под новый сайт

1. Открыть сайт вручную, найти кнопку обратного звонка.
2. Если её текст не в `form_triggers` — добавить.
3. Если submit-кнопка имеет необычный текст — добавить в `submit_button_hints`.
4. Если success-сообщение специфичное — добавить в `success_indicators`.
5. Перезапустить Streamlit (или `keywords.json` подхватится при следующем прогоне без рестарта, т.к. читается лениво).
